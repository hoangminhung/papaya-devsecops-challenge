    27	## 1. The decision in one page
    28	
    29	Engineering and Compliance disagree only about **writes to production**; reads of metadata and all
    30	of non-prod are outside Compliance's sentence (framing §3.1). Real customer data is layer 6.
    31	
    32	**Chosen approach "A + D2'"** (Options §9, owner decision 2026-11-09):
    33	
    34	1. **Default path:** every prod change is a pull request, approved by a named human who is not the
    35	   author, applied by CI. Incidents included ("IaC first").
    36	2. **Fallback (break-glass):** only when the PR path cannot be used, a human gets a 1-hour approved
    37	   grant and runs an approved command list in a terminal without an agent (layer 7) [design].
    38	3. **Nothing standing:** no human or agent holds standing prod write; no long-lived credentials.
    39	
    40	| Engineering gets | Compliance gets |
    41	|---|---|
    42	| A free loop in non-prod: read, change, deploy without approval (non-prod is synthetic, GĐ-14). | Every prod change approved **before** apply by a named human ≠ author (GĐ-8, GĐ-11), enforced in GitHub and AWS IAM, outside the agent. |
    43	| Read-only prod metadata for the agent. | No standing prod write (S1), no long-lived CI keys (S2). |
    44	| Self-service PRs, one approval, same-day ship (S4). | One evidence chain per change; approval and change records ≥ 6 years (📖 R5.2.9; applied to change records ⚠️ R5.7 #2). |
    45	| Incident lane: approval wait ≤ 15 min, 24/7 (S7). Decision-to-apply target ≤ 30 min (Options §9); current estimate 11–46 min ⚠️, measured first in rollout. | Agent-side controls as a second layer, not the control of record. |
    46	
    47	**Where the design falls short, stated openly:**
    48	
    49	- **The fallback meets the approval rule only partly** (approves a command list, not an applied
    50	  change); accepted by the owner (Options §9 Q2). It is a second, process-controlled path, while the
    51	  framing asked for one technically enforced path (framing §3.3, Options §7). It stays narrow only
    52	  if most incidents are expressible in IaC (unknown, Options §8); layer 7 measures this.
    53	- **On GitHub Team nobody sees the prod diff before apply** (⚠️ R4.6 #1; Team assumed, GĐ-5).
    54	  Risky prod diffs stop the deploy for a second approval [design].
    55	- **Admins can edit the gate**; logged, not prevented (📖 R3.2.2, ⚠️ R3.6 #1). An admin's agent has
    56	  the same power, because the agent uses its engineer's GitHub login.
    57	- **Some rules are process, not technology:** see "Process rules" in layer 1.
    58	- **HIPAA applicability is a legal question** (⚠️ R1.11.1.11); the design treats Papaya as a
    59	  business associate, as the brief implies.
    60	
    61	**Cross-cutting rules** (owner's balance principle, research 6.8):
    62	
    63	1. **The boundary is IAM and the CI gate.** Server-managed settings are "a client-side control, not
    64	   a security boundary" (📖 R1.1.7); local admins can edit endpoint files (📖 R1.1.8).
    65	2. **Assume prompt injection succeeds:** OWASP and NIST state there is no full prevention (📖 R6.1.1, R6.1.2).
    66	3. **Friction where damage is large, none where it is small**, measured, with a time-boxed escape.
    67	4. **Evidence by construction:** the path produces the records.
    68	
    69	### Roles
    70	
    71	| Role | Rule |
    72	|---|---|
    73	| Author (engineer + their agent) | Never approves own change; GitHub blocks PR authors from approving (📖 R3.3.1). |
    74	| Approver | Named human in CODEOWNERS; ≠ author, ≠ last pusher (📖 R3.2.3); for an app-opened PR, ≠ the person who triggered it (⚠️ R3.3.4, layer 5). |
    75	| On-call approver | Primary + backup, 24/7, on the on-call schedule; wait ≤ 15 min (S7). |
    76	| Platform approver [design] | Platform-team member, also on call; one of the two approvers for L3. |
    77	| Data owner [design] | Named per tenant; co-approves real-data reads (layer 6). |
    78	| Control owner | DevSecOps (1–2 people, GĐ-1); owns policies and metrics; not the only approver. |

    82	## Layer 1 — Identity and access
    83	
    84	**Principle.** Every action traces to one named human. Nobody holds standing prod write: prod is
    85	written by the pipeline role, or in the fallback by an approved, time-boxed grant. Prod reads default
    86	to metadata. No long-lived credentials. Prod and non-prod are separate boundaries.
    87	
    88	**On Papaya's stack**
    89	
    90	- **The engineer's access is the agent's access.** The agent uses the engineer's AWS SSO cache, and
    91	  one portal session reaches every role assigned to that engineer (📖 R2.2.1, R2.2.2). A separate
    92	  "agent" permission set does not separate them (⚠️ R2.9 #1). The control is what the **engineer**
    93	  holds.
    94	- **Process rules** that follow from this (owner accepted them as process controls, D2, D3):
    95	  - the JIT terminal and the real-data terminal run no agent, though the grant is reachable from the
    96	    same laptop;
    97	  - the incident-analysis session is meant to use only read-only roles;
    98	  - an agent does not approve PRs. GitHub blocks self-approval only. The auto-mode default block list
    99	    names "approving Claude's own pull request", not approving someone else's (📖 R6.3.3), and it
   100	    applies only in auto mode. No detection was found (⚠️; `actor_is_agent` in the audit log has no
   101	    documented meaning, R3.5.6).
   102	- **IAM Identity Center permission sets** (📖 R2.1.1) [design names]:
   103	  - `ProdReadMetadata`: metrics, redacted log groups, configuration; no data-plane read on claim
   104	    stores; 1 h session, the minimum (📖 R2.1.4). Lambda configuration can hold secrets resolved by
   105	    Serverless in plain text (⚠️ R4.4.7), so configuration reads are allowed per service only after
   106	    its secrets move to runtime resolution (⚠️ R4.6 #7). Cost: until then the agent reads
   107	    timeout/memory from the IaC code;
   108	  - `NonProdDeveloper`: broad, non-prod accounts only;
   109	  - `InfraOperator-<service>`: assigned only by the JIT flow (layer 7), via a partner product, the
   110	    TEAM sample or a small flow on `CreateAccountAssignment` / `DeleteAccountAssignment`
   111	    (📖 R2.4.1, R2.4.1b, R2.4.2);
   112	  - no standing prod-write permission set.
   113	- **SCPs on the prod OU** [design] (SCPs cap member-account principals, 📖 R2.3.1, R2.3.2):
   114	  - deny data-plane reads on claim stores except application roles and the approved data-read role,
   115	    by `aws:PrincipalArn` (📖 R2.3.8; pattern ⚠️ R2.9 #4). Actions, e.g. `s3:GetObject`,
   116	    `sqs:ReceiveMessage`, `states:GetExecutionHistory`, are incomplete and unchecked (⚠️ G13);
   117	  - deny `lambda:UpdateFunctionCode` / `lambda:UpdateFunctionConfiguration` (⚠️ R4.6 #3) except
   118	    CloudFormation `deploymentRole`s, the Pulumi prod deploy role (if Pulumi manages Lambdas) and the
   119	    JIT roles. This closes `serverless deploy function`, which changes config outside CloudFormation
   120	    (📖 R4.4.4), and needs `deploymentRole` set on every Serverless stack (📖 R4.4.5);
   121	  - a pre-deployed revocation Deny on `identitystore:userId` (📖 R2.4.4); protect the org trail (📖 R2.6.2).
   122	  - Limits: 10 SCPs per target, 10,240 characters; no SCP applies to the management account
   123	    (📖 R2.3.2, R2.3.4), so whatever deploys SCPs there is the most sensitive role (L3 path).
   124	- **Sessions/MFA:** portal session length set on purpose; an IdP session can extend it silently
   125	  (📖 R2.1.5, R2.1.6). MFA lives in the external IdP if one is used (📖 R2.1.7).
   126	- **CI → AWS:** GitHub OIDC, no stored keys (📖 R3.4.1). The prod role trusts only the `production`
   127	  environment of the monorepo, in its `sub` format (📖 R3.4.3, R3.4.4; immutable format assumed,
   128	  ⚠️ R3.7 A2), ideally customised with the deploy workflow's `job_workflow_ref` (📖 R3.4.5; on Team ⚠️ G10).
   129	- **CI → GCP:** Workload Identity Federation restricted to Papaya's GitHub organization, which Google
   130	  requires (📖 R3.4.5b).
   131	- **k0s, GCP and Firebase for humans:** same principles; mechanisms not researched (G1–G3). Today
   132	  k0s is reached with kubeconfigs, no SSO (GĐ-4, unconfirmed). Interim: no admin kubeconfig and no GCP
   133	  owner role on laptops; prod deploys only from CI. Firebase is not on the GCP BAA list (📖 R5.5.3), so
   134	  Firebase Hosting must hold no PHI (⚠️ R5.7 #7).
   135	
   136	**Audit evidence.** Identity Center assignment export (S1); CloudTrail `CreateAccountAssignment` /
   137	`DeleteAccountAssignment` per grant (📖 R2.4.2), linked to its approval by request ID [design]; SCPs
   138	and trust policies as Pulumi code; IAM Access Analyzer `check-no-new-access` on policy PRs
   139	(📖 R2.8.1); quarterly access review of permission sets and GitHub admins.
   140	
   141	**Cost / value.** Engineers lose standing prod write, keep fast prod reads and a free non-prod loop.
   142	Compliance gets least privilege that is enforced.

   146	## Layer 2 — Agent runtime controls
   147	
   148	**Principle.** Agent-side controls are hygiene, not the boundary. They are central, versioned in git
   149	and the same for everyone. Defaults are safe; overrides are measured. The session that reads
   150	untrusted content holds as little power as possible (📖 R6.1.2).
   151	
   152	**On Papaya's stack**
   153	
   154	- **Delivery:** server-managed settings (available on Team, 📖 R1.1.5) for all laptops. With MDM, also
   155	  an endpoint file; by default one managed source supplies most keys, so the two must carry the same
   156	  keys or use `managedSourcesBehavior: "merge"` (📖 R1.1.3, R1.1.4). MDM is unknown; both are prepared.
   157	- **Baseline** (template: Anthropic's `settings-hipaa.json`, 📖 R5.5.4). All keys 📖 at the row cited:
   158	
   159	  | Key | Value and reason |
   160	  |---|---|
   161	  | `permissions.defaultMode` | `default` (Manual). A default, not a lock: users can switch to auto; VS Code remembers the last pick (D1, R6.9.3). |
   162	  | `permissions.allow` | Read-only commands Papaya uses, to cut prompts (R6.9.3). |
   163	  | `allowManagedPermissionRulesOnly` | `true`, one rule set (D1, owner Q4; R1.2.5). Cost: project and user rules are ignored, so the managed set must carry every deny/ask rule projects need; prompts likely rise (⚠️ research 6.9.4 Q4). |
   164	  | `permissions.disableBypassPermissionsMode` | `"disable"`: removes "prompts off" (P3a; R1.2.2). Auto mode stays available (D1). |
   165	  | `permissions.deny` / `ask` | Deny credential paths (R5.5.4; `Read(...)` syntax ⚠️ R1.8 #5). Ask for `WebFetch`, which the sandbox domain list does not limit (R1.6.2); cost: a prompt per fetch. |
   166	  | `requiredMinimumVersion` | ≥ 2.1.295 (`onFailure: "block"`, R1.5.2) and ≥ the latest fixed advisory at rollout (R6.3.9). It does not end running sessions and fails open on a bad value (R1.1.13). |
   167	  | `allowedProviders` + `forceLoginOrgUUID` | `["anthropic"]` + Papaya's org; closes most bypasses on **endpoint-managed** machines (R1.1.15). |
   168	  | `allowManagedHooksOnly` | `true` (R1.5.4). |
   169	  | sandbox | `sandbox.enabled`, `failIfUnavailable`, `allowUnsandboxedCommands: false`, narrow `network.allowedDomains` locked by `network.allowManagedDomainsOnly` (R1.6.4); `credentials` / `filesystem.denyRead` on `~/.aws` (R1.6.3). |
   170	  | MCP, plugins | Layer 4. |
   171	  | OTel | Exporter on, content flags `0` (R1.1.20, R5.5.4). |
   172	
   173	- **Trade-off on AWS credentials.** With `~/.aws` hidden from the sandbox, `aws`, `pulumi` and
   174	  `serverless` must be `sandbox.excludedCommands`, which run "with full access", network included
   175	  (📖 R1.6.4). So these tools are an egress channel outside the allowlist. Accepted because the
   176	  engineer holds no prod write and no PHI read; the deny still stops other programs from taking the
   177	  credentials. Stronger option, phase 3: a separate OS user or container for prod-reading sessions
   178	  (⚠️ R6.5 #2).
   179	- **Session types:**
   180	
   181	  | Session | Identity | Flags | Enforcement |
   182	  |---|---|---|---|
   183	  | Daily development (laptop) | non-prod roles + `ProdReadMetadata` | baseline | Auto mode by choice (D1); `--restricted` recommended (D3). |
   184	  | Incident analysis (laptop) | meant to be `ProdReadMetadata` only | `--restricted --tools "Bash,Read,Grep,Glob"`, started in an empty scratch directory, not the repo [design] | Process rule (D3, owner Q1–Q2). No Edit/Write/WebFetch (📖 R6.9.1b), but Bash can still write in its working directory (📖 R1.6.3) and call any role in the cache. |
   185	  | CI agent (hosted runner) | own GitHub App token; never `production` | `--restricted`, explicit `--tools`; all rules in a managed-settings file on the runner | Workflow file under CODEOWNERS (D3, owner Q5). The file is advisory if `Bash` is in `--tools` (layer 5). |
   186	  | JIT terminal | JIT grant | no agent | Process rule (D2). |
   187	  | Auto-mode environment (phase 3) | non-prod only | auto encouraged | D1 option (c). |
   188	
   189	- **Hard limits:** Bash rules are not a boundary (📖 R1.2.6); hooks fail open unless
   190	  `"onFailure": "block"` (📖 R1.5.2); `--restricted` cannot be forced on laptops (📖 R6.9.1, R6.9.1c);
   191	  on laptops **without MDM**, a different login, an API key or a `CLAUDE_CODE_USE_*` variable skips
   192	  server-managed settings, `allowedProviders` included (📖 R1.1.7; ⚠️ R1.8 #3, G11). So S5's
   193	  "nobody can turn off all prompts unnoticed" is likely unreachable without MDM (⚠️).
   194	- **Auto memory:** engineers review it and delete it after a suspicious session; residual risk with a
   195	  named owner (D3).
   196	- **Fallback:** switch to `disableAutoMode` if the planted-injection test steers auto mode, a serious
   197	  advisory appears, or an audit finds auto mode touched a protected scope (D1).
   198	
   199	**Audit evidence.** Managed settings in git with PR approvals; `/status` and `claude doctor` from
   200	sampled machines (📖 R1.1.18); OTel `claude_code.tool_decision` (`permission_mode`) and
   201	`claude_code.tool.blocked_on_user` (`duration_ms`, rubber-stamping signal) (fields 📖 research 6.6
   202	D1 metrics; thresholds ⚠️). Settings-change audit events on Team: unknown (⚠️ R1.1.12).
   203	
   204	**Cost / value.** More prompts than auto mode, partly offset by the read-only allowlist. Compliance
   205	gets one organization policy with evidence instead of personal choices (P3c).

   209	## Layer 3 — Change workflow by risk level
   210	
   211	**Principle.** The level is set by the damage a change can do. One default path above non-prod: a
   212	reviewed PR applied by the pipeline, with the JIT fallback (layer 7) as the only other write path.
   213	The approver reviews the code change that will be applied. Higher risk adds a second, specialised
   214	approver. Incidents use the same path with faster people, not fewer security checks.
   215	
   216	| Level | What | Examples | Approval | Path |
   217	|---|---|---|---|---|
   218	| **L0** | Read: non-prod anything; prod metadata | metrics, redacted logs | none | read-only identity |
   219	| **L1** | Change in non-prod | deploy a branch to dev; `pulumi preview` on non-prod (it writes state, 📖 R4.3.3) | author only | non-prod roles or PR pipeline |
   220	| **L2** | Routine prod change in code | Lambda timeout/memory, ECS desired count, release, `CLAUDE.md` | 1 code owner ≠ author, ≠ last pusher | PR → `main` → deploy workflow |
   221	| **L3** | High-risk prod change | IAM/SCP; replace/delete of stateful resources; network; `.github/**`, CODEOWNERS, `.claude/**`, `.mcp.json`, plugin/MCP catalogue; policy violation | 2 distinct humans, at least one platform approver | same path, second approval by path rule or risk stop |
   222	| **L3-JIT** | Break-glass | ECS force-redeploy while Actions is down | on-call approver ≠ requester (Options §4b) | layer 7 |
   223	| **L3-data** | Real customer data read | one tenant's failed claim record | data owner + approver ≠ requester, with an agreement (GĐ-9) | layer 6 |
   224	
   225	`CLAUDE.md` is L2, not L3, so that moving shared knowledge into it (D3) stays cheap.
   226	
   227	**On Papaya's stack**
   228	
   229	- **Gate = merge to `main`.** On Team, environment reviewers do not exist for private repos
   230	  (📖 R3.1.2). Ruleset on `main`: PR required, 1 approval, code-owner review, dismiss stale approvals,
   231	  approval by someone other than the last pusher, required checks from a pinned source app, no force
   232	  push, empty bypass list (📖 R3.2.2, R3.2.3, R3.2.5). Branch up to date before merge, since there is
   233	  no merge queue (⚠️ R4.6 #1; whether updating drops approvals is open, Options §8).
   234	- **L3 approvals [design]:** a path rule requires 1 platform approval on L3 paths (📖 R3.2.4). Because
   235	  any one code owner satisfies code-owner review (📖 R3.2.7), one platform member could satisfy both
   236	  rules alone (⚠️ inference); a required check with a pinned source app (📖 R3.2.5) therefore confirms
   237	  two distinct human approvers. At 2 a.m. this needs the platform on-call plus one other approver.
   238	- **Risk stop [design]:** the deploy job previews prod; on stateful replace/delete, an IAM change or a
   239	  policy violation it stops. A second PR adds `deploy-approvals/<sha>.yaml` with the preview hash; a
   240	  platform approver other than the first approver approves (checked as above); the job continues only
   241	  if the hash matches (Options §1; hash stability ⚠️ Options §8). Preview output is filtered for
   242	  outputs and secrets before it is posted (Options §1; ⚠️ R4.6 #2).
   243	- **Merge approval = deploy approval** only if (⚠️ R3.6 #1, from 📖 R3.1.3, R3.4.5c): `production`
   244	  allows only `main`; only the reusable deploy workflow (under CODEOWNERS) references it; no ref/SHA
   245	  inputs; no `issue_comment`, `pull_request_target` or `workflow_run` triggers; one concurrency group
   246	  per stack without `cancel-in-progress` (📖 R4.1.4).
   247	- **Pulumi:** PRs preview non-prod only, because a prod preview runs PR code with state-write and
   248	  secret access (📖 R4.3.3, R4.3.4; ⚠️ R4.6 #2). On `main`: prod preview, then `pulumi up` with the
   249	  policy pack, which stops on a mandatory violation (📖 R4.2.2). Prod runs allow no `--skip-preview`
   250	  (📖 R4.1.2) and no targeting, replace, `state`, `import`, `destroy` (⚠️ R4.6 #3, G12). Pulumi Cloud,
   251	  if used: OIDC via `pulumi/auth-actions`, no stored token (📖 R4.1.4).
   252	- **Serverless v4:** `serverless package`; `serverless diff --json` (sf-core ≥ 4.37.0), parsed by CI
   253	  because differences do not change the exit code (📖 R4.4.2); `serverless deploy --package`
   254	  (📖 R4.4.3); a least-privilege `deploymentRole`, which cannot be removed later and is usable by
   255	  anyone who may operate the stack (📖 R4.4.5), so JIT roles get no stack-operation rights.
   256	- **State:** writable only by deploy roles; readable also by the drift role (layer 7); Pulumi
   257	  secrets via `awskms` on a DIY backend (📖 R4.3.3, R4.3.4; ⚠️ R4.6 #7).
   258	- **k0s [design]:** manifests in the monorepo, applied by CI; no write RBAC for humans or agents in
   259	  prod; read roles exclude logs and exec in namespaces with claim data (mechanism: G1).
   260	- **Incident lane:** label `incident`, on-call approver paged, security checks always run (S10), only
   261	  slow unrelated tests skipped [design].
   262	
   263	**Example: Lambda timeouts at 2 a.m.** (Options §6)
   264	
   265	1. The incident-analysis session reads metrics and redacted logs and proposes `timeout` 30 → 90 s,
   266	   memory 1024 → 2048 MB, and a larger visibility timeout on the source queue (ratio ⚠️ Options §8).
   267	2. A second session (edit tools; not meant to use prod roles) edits `serverless.yml`, runs
   268	   `serverless diff` on non-prod, and opens a PR labelled `incident` as the engineer.
   269	3. The on-call approver reviews the diff, and can catch a missing queue change, then approves.
   270	4. The deploy workflow packages, previews prod, finds no risky change, deploys with the OIDC role.
   271	5. Estimate 11–46 min (⚠️ Options §6) against ≤ 30 min: measured first in rollout.
   272	
   273	**Audit evidence.** The PR (diff, approvers, checks); run log and preview artifact, exported because
   274	retention is unverified (⚠️ G7); deploy-role CloudTrail events; all linked by commit SHA and run ID.
   275	
   276	**Cost / value.** One approval for routine prod changes, two for risky ones, none in non-prod.
   277	Compliance gets four-eyes enforced by GitHub. Gap: on Team the prod diff is not seen before apply.

   281	## Layer 4 — Supply chain for MCP servers and plugins
   282	
   283	**Principle.** MCP servers, plugins and hooks run with the engineer's access (📖 R1.6.2, R5.5.5).
   284	Only reviewed, pinned entries from a catalogue are allowed. The catalogue is the inventory (P4c).
   285	Review takes ≤ 5 working days (S6), or people work around it.
   286	
   287	**On Papaya's stack**
   288	
   289	- **Plugins:** a private marketplace repo with `.claude-plugin/marketplace.json` (📖 R1.4.1), sources
   290	  pinned to `ref`/`sha` (📖 R1.4.1b, link only). Managed `strictKnownMarketplaces` = Papaya only,
   291	  `blockedMarketplaces`, `enabledPlugins: false` to pull one (📖 R1.4.2), checked before download and
   292	  at session start (📖 R1.4.3). `disableSideloadFlags` rejects `--plugin-dir`, `--plugin-url`,
   293	  `--agents`, `--mcp-config` but not `.mcp.json` or `claude mcp add` (📖 R1.4.2). With
   294	  `allowManagedHooksOnly`, plugin hooks run only for force-enabled plugins (📖 R1.5.4). User mods are
   295	  blocked by the `allowManagedModsOnly` option under `pluginConfigs` → `cc-plugin-sec-default@builtin`
   296	  → `options` (📖 R1.5.6). The version floor covers the plugin-pin fix of 2.1.179 (📖 R6.2.7).
   297	- **MCP:** "approved catalogue" = `allowedMcpServers` + `allowManagedMcpServersOnly: true`; without
   298	  the lock users can widen it (📖 R1.3.1, R1.3.4). Match by `serverUrl` or `serverCommand`, never

   318	## Layer 5 — CI/CD hardening
   319	
   320	**Principle.** CI is the default production writer, so it is the main target. Short-lived,
   321	least-privilege credentials per job. Every CI dependency is pinned. Agent-written code passes the same
   322	checks as human code (S10).
   323	
   324	**On Papaya's stack**
   325	
   326	- **Credentials:** OIDC instead of keys and tokens in repository secrets, which any writer can read
   327	  (📖 R3.4.1, R3.5.3b). `GITHUB_TOKEN` "restricted" by default, `permissions:` per job (📖 R3.5.3).
   328	  "Allow GitHub Actions to create and approve pull requests" off (📖 R3.3.3). Serverless License Key in
   329	  SSM, read by the deploy role (sf ≥ 4.4.19, 📖 R4.4.8). Until G1/G2 are solved, k0s and Firebase
   330	  deploys may still need a stored credential: a proposed time-boxed exception to S2 = 0 (Q1).
   331	- **Side paths:** Pulumi ESC, Pulumi Deployments and Serverless Dashboard providers reach AWS
   332	  (📖 R4.4.9) outside the GitHub gate (⚠️ R4.4.9); not used for prod (⚠️ R4.6 #6).
   333	- **Pinning:** workflow lockfile (`gh actions-lock`) or full SHA, enforced by the org policy "Require
   334	  actions to be pinned to a full-length commit SHA"; the lockfile does not pin reusable workflows, so
   335	  the deploy workflow lives in the same repo (📖 R3.5.5).
   336	- **CODEOWNERS** on `.github/`, `CLAUDE.md`, `CLAUDE.local.md`, `.claude/`, `.claude.json`, `.mcp.json`,
   337	  `.husky/`, `.gitmodules`, `.ripgreprc` (📖 R3.2.8; list ⚠️ R6.5 #5); CI validates the file, because
   338	  invalid lines are skipped silently (📖 R3.2.7).
   339	- **No privileged triggers with untrusted code** (`pull_request_target`, `workflow_run` + checkout,
   340	  📖 R3.5.4).
   341	- **Agents in CI:** `claude-code-action` with a custom GitHub App limited to Contents, Issues, Pull
   342	  requests (📖 R1.7.8); Anthropic workload identity federation, not a personal OAuth token (📖 R1.7.6);
   343	  `--restricted` and explicit `--tools` (D3; passing it through `claude_args` unverified, ⚠️ research
   344	  6.9.4 Q5); a managed-settings file on the runner, which also guards against mods (📖 R1.5.6; for
   345	  federation auth ⚠️); MCP set fixed by CI because `.mcp.json` loads without a prompt in `-p` runs
   346	  (📖 R1.3.5); never `environment: production` (⚠️ R3.6 #4). Hosted runners give `sudo` (📖 R3.5.1),
   347	  so with `Bash` in `--tools` the runner file is advisory (⚠️ R3.5.1, R3.6 #4).
   348	- **App-opened PRs:** a required check with a pinned source app confirms at least one approval by a
   349	  human who did not trigger the run; counting approvals is not enough, since the app's own approval
   350	  might count (⚠️ R3.3.4, R3.7 A3; 📖 R3.2.5).
   351	- **Required checks (S10):** secret scanning, dependency check, SAST (products: G4); IAM Access
   352	  Analyzer `check-no-new-access` (📖 R2.8.1); Pulumi policy packs (📖 R4.2.2).
   353	
   354	**Audit evidence.** Workflows and lockfile in git; audit-log events such as
   355	`org.update_actions_secret`, `repo.set_workflow_permission_can_approve_pr`, `repository_ruleset.update`
   356	(📖 R3.3.3, R3.5.6); check results per PR; secrets inventory (S2).
   357	
   358	**Cost / value.** One-time migration to OIDC and pinned actions; slower action updates. Compliance
   359	gets S2 and the same guardrails for agent and human code.

   363	## Layer 6 — Data protection and prompt-injection defence
   364	
   365	**Principle.** PHI never reaches the coding agent (owner decision, research 1.9). Other customer
   366	personal data is outside that hard boundary ("not extended", research 5.8): the agent reads metadata
   367	by default and may read such data case by case under GĐ-9. Real-data reads are approved,
   368	tenant-scoped, time-boxed, and need an agreement (BAA/DPA, partner contract) (GĐ-9). Everything read
   369	from outside is untrusted. Non-prod is synthetic (GĐ-14).
   370	
   371	**On Papaya's stack**
   372	
   373	- **Paths to PHI** (research 1.11.4 lists 17):
   374	  - AWS stores: closed by identity, through `ProdReadMetadata` from phase 1 and the SCP from phase 2
   375	    (layer 1); no Aurora credentials, no prod exec, no `lambda:InvokeFunction` for agent-usable roles
   376	    [design; actions ⚠️ G13];
   377	  - k0s logs/exec and GCP stores (L1, L11, L13): same principle, mechanism open (G1, G3);
   378	  - tickets/chat via MCP, pasted text, internal admin pages, prod AI traces, fixtures, CI logs (L5,
   379	    L8–L10, L12, L14): process and hygiene only;
   380	  - logs redacted at source with raw payloads in a separate log group; alerts carry IDs, not payloads [design].
   381	- **Real-data request** [design]: tenant, purpose, store, window, agreement; approved by the data owner
   382	  and an approver ≠ requester; JIT data-read role, 1 h. Per-tenant scoping through session tags
   383	  (📖 R2.1.8) is unresolved, because tags come from user attributes (⚠️).
   384	  - **PHI:** a human reads in a terminal without an agent; the agent gets a redacted summary. This
   385	    narrows GĐ-9 because the agent stays outside PHI scope (research 1.9) and Team is not shown as
   386	    BAA-covered (⚠️ R1.11.3.4). Enterprise + BAA only for a separate environment if needed (research 1.9).
   387	  - **Non-PHI personal data:** the agent may read it within the approved request (GĐ-9).
   388	- **Partner-uploaded claim documents (A7b):** never in an agent session raw; reproduce with synthetic
   389	  documents, or de-identify first [design]. The document is PHI and an injection vector (research
   390	  1.11.4 L6).
   391	- **Injection** (these lower frequency; layers 1 and 3 limit impact): Manual by default; the auto-mode
   392	  classifier missed 17 % of 52 real overeager actions (📖 R6.3.5). Broad allowed domains such as
   393	  `github.com` are a documented exfiltration path (📖 R6.3.7). The incident session has no edit tools
   394	  and runs outside the repo, but its Bash can still write locally and send data out through excluded
   395	  commands (layer 2); what is at stake is bounded by "no standing write, no PHI read". Shared knowledge
   396	  goes in `CLAUDE.md` under review; auto memory is unprotected unless `--restricted` (📖 R6.3.11, D3).
   397	- **Tenants:** one tenant per data-read grant; a session that read one tenant's data does not post to
   398	  shared places without review (⚠️ R6.5 #8, process). Logical separation in shared accounts is assumed
   399	  (GĐ-3).
   400	- **Non-prod:** no prod copies (S11). A scan of non-prod stores runs at the start of phase 1 (tool:
   401	  G4); a store not yet scanned follows the L3-data rule (GĐ-14). Cost: until scanned, that store is
   402	  not part of the free loop.
   403	- **Local stores:** transcripts and memory hold what the agent read (research 1.11.4); set
   404	  `cleanupPeriodDays` (30 in the HIPAA sample, 📖 R5.5.4; what it deletes ⚠️).
   405	- **Cross-border (Vietnam example):** processing data collected in Vietnam on a platform abroad is a
   406	  transfer (📖 R5.4.5); agent flows, including employee names in logs and transcripts, update the
   407	  transfer impact assessment (⚠️ R5.7 #4, needs Papaya legal).
   408	
   409	**Audit evidence.** SCP/IAM text as the written access rule for sensitive data (📖 R5.4.3; ⚠️ R5.7 #5);
   410	data-read requests and the data-read role's CloudTrail; planted-injection reports (layer 8); non-prod
   411	scan results (S11).
   412	
   413	**Cost / value.** Debugging with redacted and synthetic data; a request for the rare real-data read.
   414	Compliance gets "minimum necessary" (📖 R1.11.1.8) enforced by IAM, and a record per exception (S9).

   418	## Layer 7 — Observability, audit, incident response and break-glass
   419	
   420	**Principle.** One tamper-evident evidence chain per prod change. One routed alert channel with a
   421	named on-call, approvers included. Unapproved change is detected (drift, reconciliation). Break-glass
   422	is approved before use, time-boxed and reconciled after.
   423	
   424	**On Papaya's stack**
   425	
   426	- **Audit stores:**
   427	  - organization CloudTrail to a log-archive account with integrity validation (📖 R2.6.2, R2.6.4,
   428	    R2.6.5); change records ≥ 6 years; raw-log retention for Papaya's compliance owner (⚠️ R5.7 #2).
   429	    Data events only on PHI buckets, prod Lambda invoke and prod SQS (📖 R2.6.3), which makes the archive
   430	    PHI-bearing (⚠️ research 1.11.4 L15). CloudTrail Lake is closed to new customers (📖 R2.6.6);
   431	  - GitHub org audit log kept 180 days, so exported (📖 R3.5.6);
   432	  - alerts on `repository_ruleset.update`, `environment.update_protection_rule`,
   433	    `environment.remove_protection_rule`, `environment.delete`, `protected_branch.policy_override`
   434	    (📖 R3.5.6, R3.1.4; selection ⚠️ R3.6 #1). UI changes to the branch policy may leave no event, and a
   435	    deleted `production` environment comes back unprotected (⚠️ R3.1.4): a job compares live settings
   436	    with an expected copy (G8);
   437	  - Aurora SQL is likely invisible to CloudTrail (⚠️ R2.7.1): Database Activity Streams, alerts on
   438	    lost-record events, stream treated as PHI (📖 R2.7.2; Serverless v2 ⚠️);
   439	  - Claude Code OTel without prompt content (layer 2).
   440	- **Change record [design]:** keyed by commit SHA or JIT request ID; links PR, approvals, run ID,
   441	  preview and CloudTrail events. Monthly reconciliation: every prod write event matches a record
   442	  approved before apply (S3). Actor: `onBehalfOf.userId` where present, else session name plus
   443	  directory lookup (📖 R2.5.1; ⚠️ R2.5.3).
   444	- **Drift [design]:** its own read role, trusted only from a `drift` environment on `main`; it can read
   445	  prod secrets in state, which is noted (⚠️ R4.6 #2). Scheduled `pulumi preview --refresh
   446	  --expect-no-changes` or `pulumi refresh --preview-only` (📖 R4.1.1, R4.3.1, R4.3.2); CloudFormation
   447	  drift detection, explicitly set properties only (📖 R4.4.6). No auto-remediation: it is an unreviewed
   448	  `pulumi up --refresh` (📖 R4.3.2). Each finding gets an actor and a ticket.
   449	- **On-call:** phase 1 delivers only the named approver schedule (primary + backup, 24/7), as decided
   450	  in framing round 1, including a platform approver because L3 needs one (Options §1). Alert routing and
   451	  the rest of on-call follow in phase 2 (tools: G5).
   452	- **Break-glass = JIT fallback** [design unless marked]:
   453	
   454	  | Step | Rule |
   455	  |---|---|
   456	  | When | The PR path cannot be used: operation not in IaC and no runbook; GitHub/Actions down; pipeline broken. The approver refuses JIT for anything expressible in IaC while the pipeline works, and records why. |
   457	  | Request | Command list, scope, reason, incident link, in a channel that does not depend on GitHub. |
   458	  | Approval | On-call approver ≠ requester, before the grant. |
   459	  | Grant | `InfraOperator-<service>`, 1 h (📖 R2.1.4). Deleting the assignment likely stops only new sessions (⚠️ R2.4.2, R2.9 #3); ending the portal session does not end role sessions (📖 R2.4.3); an immediate stop needs the revocation SCP (📖 R2.4.4). |
   460	  | Execution | The human types the commands; no agent in that terminal (D2). |
   461	  | After | A job compares CloudTrail writes in the window with the list; a codify PR within a fixed deadline (as soon as GitHub is back); drift detection until it merges. |
   462	  | Identity Center outage | Emergency SAML federation to roles, built and tested in advance (📖 R2.1.11; ⚠️ R2.9 #2); no user mapped until an approved activation, which is alerted. |
   463	
   464	  **Example request (illustrative command ⚠️):** "INC-123, `claims-doc-extract`, Actions outage. Run
   465	  `aws ecs update-service --cluster <prod-cluster> --service <svc> --force-new-deployment`. Scope
   466	  `InfraOperator-claims`, 1 h."
   467	
   468	  **Metrics** (Options §7; starting thresholds ⚠️ to calibrate): JIT used where a PR was possible
   469	  (review at 1); writes outside the list (review at 1); codify PRs late (review at 1); grants per
   470	  month and share of incidents needing non-IaC operations (review above about 25 %). On a breach,
   471	  make the PR lane faster or add a runbook; do not widen JIT.
   472	- **Roadmap:** runbooks for repeated non-IaC operations, if SSM Automation's approval step meets three
   473	  conditions (Options §2; outside 02-research, G6); break-glass from an environment without the agent
   474	  (D2, ⚠️).
   475	
   476	**Audit evidence.** Validated CloudTrail; exported GitHub audit log; change records and monthly
   477	reconciliation (S3, S8 ≤ 30 min); JIT requests, reconciliations, codify PRs; drift tickets; on-call
   478	schedule and approval waits (S7).
   479	
   480	**Cost / value.** The incident lane is slower than direct access (estimated 11–46 vs 2–20 min,
   481	Options §6), and JIT needs a written command list. Compliance gets approval before apply even in
   482	incidents, plus detection.
