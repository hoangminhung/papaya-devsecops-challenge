    28	## 1. The decision in one page
    29	
    30	Engineering and Compliance disagree only about **writes to production**; reads of metadata and all
    31	of non-prod are outside Compliance's sentence (framing §3.1). Real customer data is layer 6.
    32	
    33	**Chosen approach "A + D2'"** (Options §9, owner decision 2026-11-09):
    34	
    35	1. **Default path:** every prod change is a pull request, approved by a named human who is not the
    36	   author, applied by CI. Incidents included ("IaC first").
    37	2. **Fallback (break-glass):** only when the PR path cannot be used, a human gets a 1-hour approved
    38	   grant and runs an approved command list in a terminal without an agent (layer 7) [design].
    39	3. **Nothing standing:** no human or agent holds standing prod write; no long-lived credentials.
    40	
    41	| Engineering gets | Compliance gets |
    42	|---|---|
    43	| A free loop in non-prod: read, change, deploy without approval (non-prod is synthetic or masked, GĐ-14). | Every prod change approved **before** apply by a named human ≠ author (GĐ-8, GĐ-11), enforced in GitHub and AWS IAM, outside the agent (limits below). |
    44	| Read-only prod metadata for the agent. | No standing prod write (S1), no long-lived CI keys (S2; exception pending OQ1). |
    45	| Self-service PRs, one approval, same-day ship (S4). | One evidence chain per change; approval and change records ≥ 6 years (📖 R5.2.9; applied to change records ⚠️ R5.7 #2). |
    46	| Incident lane: approval wait ≤ 15 min, 24/7 (S7). Decision-to-apply target ≤ 30 min (Options §9); current estimate 11–46 min ⚠️, measured first in rollout. | Agent-side controls as a second layer, not the control of record. |
    47	
    48	**Where the design falls short, stated openly:**
    49	
    50	- **The fallback meets the approval rule only partly** (approves a command list, not an applied
    51	  change); accepted by the owner (Options §9 Q2). It is a second, process-controlled path, while the
    52	  framing asked for one technically enforced path (framing §3.3, Options §7). It stays narrow only
    53	  if most incidents are expressible in IaC (unknown, Options §8); layer 7 measures this.
    54	- **On GitHub Team nobody sees the prod diff before apply** (⚠️ R4.6 #1; Team assumed, GĐ-5).
    55	  Risky prod diffs stop the deploy for a second approval [design].
    56	- **Admins can edit the gate**; logged, not prevented (📖 R3.2.2, ⚠️ R3.6 #1). An admin's agent has
    57	  the same power, because the agent uses its engineer's GitHub login.
    58	- **Some rules are process, not technology:** see "Process rules" in layer 1. In particular, that the
    59	  approval comes from a human and not from an agent using that human's login is a process rule.
    60	- **Incident approvers vs domain review:** for the on-call approver to approve any path at 2 a.m.,
    61	  they must be a code owner of every deployable path, which weakens domain review on normal days. No
    62	  verified solution yet (Options §1, §7, §8); S7 depends on it.
    63	- **HIPAA applicability is a legal question** (⚠️ R1.11.1.11); the design treats Papaya as a
    64	  business associate, as the brief implies.
    65	
    66	**Cross-cutting rules** (owner's balance principle, research 6.8):
    67	
    68	1. **The boundary is IAM and the CI gate.** Server-managed settings are "a client-side control, not
    69	   a security boundary" (📖 R1.1.7); local admins can edit endpoint files (📖 R1.1.8).
    70	2. **Assume prompt injection succeeds:** neither OWASP nor NIST knows a full prevention (📖 R6.1.1, R6.1.2).
    71	3. **Friction where damage is large, none where it is small**, measured, with a time-boxed escape.
    72	4. **Evidence by construction:** the path produces the records.
    73	
    74	### Roles
    75	
    76	| Role | Rule |
    77	|---|---|
    78	| Author (engineer + their agent) | Never approves own change; GitHub blocks PR authors from approving (📖 R3.3.1). |
    79	| Approver | Named human in CODEOWNERS; ≠ author, ≠ last pusher (📖 R3.2.3); for an app-opened PR, ≠ the person who triggered it (⚠️ R3.3.4, layer 5). |
    80	| On-call approver | Primary + backup, 24/7, on the on-call schedule; wait ≤ 15 min (S7). |
    81	| Platform approver [design] | Platform-team member, also on call; one of the two approvers for L3. |
    82	| Data owner [design] | Named per tenant; co-approves real-data reads (layer 6). |
    83	| Control owner | DevSecOps (1–2 people, GĐ-1); owns policies and metrics; not the only approver. |

    87	## Layer 1 — Identity and access
    88	
    89	**Principle.** Every action traces to one named human. Nobody holds standing prod write: prod is
    90	written by the pipeline role, or in the fallback by an approved, time-boxed grant. Prod reads default
    91	to metadata. No long-lived credentials. Prod and non-prod are separate boundaries.
    92	
    93	**On Papaya's stack**
    94	
    95	- **The engineer's access is the agent's access.** The agent uses the engineer's AWS SSO cache, and
    96	  one portal session reaches every role assigned to that engineer (📖 R2.2.1, R2.2.2). A separate
    97	  "agent" permission set does not separate them (⚠️ R2.9 #1). The control is what the **engineer**
    98	  holds.
    99	- **Process rules** that follow from this (owner accepted them as process controls, D2, D3):
   100	  - the JIT terminal and the real-data terminal run no agent, though the grant is reachable from the
   101	    same laptop;
   102	  - the incident-analysis session is meant to use only read-only roles;
   103	  - an agent does not approve PRs. GitHub blocks self-approval only. The auto-mode default block list
   104	    names "approving Claude's own pull request", not approving someone else's (📖 R6.3.3), and it
   105	    applies only in auto mode. No detection was found (⚠️; `actor_is_agent` in the audit log has no
   106	    documented meaning, R3.5.6).
   107	- **IAM Identity Center permission sets** (📖 R2.1.1) [design names]:
   108	  - `ProdReadMetadata`: metrics, redacted log groups, configuration; no data-plane read on claim
   109	    stores; 1 h session, the minimum (📖 R2.1.4). Until a service's logs are redacted at source
   110	    (layer 6), it gets that service's metrics only. Lambda configuration can hold secrets resolved by
   111	    Serverless in plain text (⚠️ R4.4.7), so configuration reads are allowed per service only after
   112	    its secrets move to runtime resolution (⚠️ R4.6 #7). Cost: until then the agent reads
   113	    timeout/memory from the IaC code;
   114	  - `NonProdDeveloper`: broad, non-prod accounts only;
   115	  - `InfraOperator-<service>`: assigned only by the JIT flow (layer 7), via a partner product, the
   116	    TEAM sample or a small flow on `CreateAccountAssignment` / `DeleteAccountAssignment`
   117	    (📖 R2.4.1, R2.4.1b, R2.4.2);
   118	  - no standing prod-write permission set.
   119	- **SCPs on the prod OU** [design] (SCPs cap member-account principals, 📖 R2.3.1, R2.3.2):
   120	  - deny data-plane reads on claim stores except application roles and the approved data-read role,
   121	    by `aws:PrincipalArn` (📖 R2.3.8; pattern ⚠️ R2.9 #4). Actions, e.g. `s3:GetObject`,
   122	    `sqs:ReceiveMessage`, `states:GetExecutionHistory`, are incomplete and unchecked (⚠️ G13);
   123	  - deny `lambda:UpdateFunctionCode` / `lambda:UpdateFunctionConfiguration` (⚠️ R4.6 #3) except
   124	    CloudFormation `deploymentRole`s, the Pulumi prod deploy role (if Pulumi manages Lambdas) and the
   125	    JIT roles. This closes `serverless deploy function`, which changes config outside CloudFormation
   126	    (📖 R4.4.4), and needs `deploymentRole` set on every Serverless stack (📖 R4.4.5);
   127	  - a pre-deployed revocation Deny on `identitystore:userId` (📖 R2.4.4); protect the org trail (📖 R2.6.2).
   128	  - Limits: 10 SCPs per target, 10,240 characters; no SCP applies to the management account
   129	    (📖 R2.3.2, R2.3.4), so whatever deploys SCPs there is the most sensitive role (L3 path).
   130	- **Sessions/MFA:** portal session length set on purpose; an IdP session can extend it silently
   131	  (📖 R2.1.5, R2.1.6). MFA lives in the external IdP if one is used (📖 R2.1.7).
   132	- **CI → AWS:** GitHub OIDC, no stored keys (📖 R3.4.1). The prod role trusts only the `production`
   133	  environment of the monorepo, in its `sub` format (📖 R3.4.3, R3.4.4; immutable format assumed,
   134	  ⚠️ R3.7 A2), ideally customised with the deploy workflow's `job_workflow_ref` (📖 R3.4.5; on Team ⚠️ G10).
   135	- **CI → GCP:** Workload Identity Federation restricted to Papaya's GitHub organization, which Google
   136	  requires (📖 R3.4.5b).
   137	- **k0s, GCP and Firebase for humans:** same principles; mechanisms not researched (G1–G3). Today
   138	  k0s is reached with kubeconfigs, no SSO (GĐ-4, unconfirmed). Interim: no admin kubeconfig and no GCP
   139	  owner role on laptops; prod deploys only from CI. Firebase is not on the GCP BAA list (📖 R5.5.3), so
   140	  Firebase Hosting must hold no PHI (⚠️ R5.7 #7).
   141	
   142	**Audit evidence.** Identity Center assignment export (S1); CloudTrail `CreateAccountAssignment` /
   143	`DeleteAccountAssignment` per grant (📖 R2.4.2), linked to its approval by request ID [design]; SCPs
   144	and trust policies as Pulumi code; IAM Access Analyzer `check-no-new-access` on policy PRs
   145	(📖 R2.8.1); quarterly access review of permission sets and GitHub admins.
   146	
   147	**Cost / value.** Engineers lose standing prod write, keep fast prod reads and a free non-prod loop.
   148	Compliance gets least privilege that is enforced.

   152	## Layer 2 — Agent runtime controls
   153	
   154	**Principle.** Agent-side controls are hygiene, not the boundary. They are central, versioned in git
   155	and the same for everyone. Defaults are safe; overrides are measured. The session that reads
   156	untrusted content holds as little power as possible (📖 R6.1.2).
   157	
   158	**On Papaya's stack**
   159	
   160	- **Delivery:** server-managed settings (available on Team, 📖 R1.1.5) for all laptops. With MDM, also
   161	  an endpoint file; by default one managed source supplies most keys, so the two must carry the same
   162	  keys or use `managedSourcesBehavior: "merge"` (📖 R1.1.3, R1.1.4). MDM is unknown; both are prepared.
   163	- **Baseline** (template: Anthropic's `settings-hipaa.json`, 📖 R5.5.4). All keys 📖 at the row cited:
   164	
   165	  | Key | Value and reason |
   166	  |---|---|
   167	  | `permissions.defaultMode` | `default` (Manual). A default, not a lock: users can switch to auto; VS Code remembers the last pick (D1, R6.9.3). |
   168	  | `permissions.allow` | Read-only commands Papaya uses, to cut prompts (R6.9.3). |
   169	  | `allowManagedPermissionRulesOnly` | `true`, one rule set (D1, research 6.9.4 Q4; R1.2.5). Cost: project and user rules are ignored, so the managed set must carry every deny/ask rule projects need; prompts likely rise (⚠️ research 6.9.4 Q4). |
   170	  | `permissions.disableBypassPermissionsMode` | `"disable"`: removes "prompts off" (P3a; R1.2.2). Auto mode stays available (D1). |
   171	  | `permissions.deny` / `ask` | Deny credential paths (R5.5.4; `Read(...)` syntax ⚠️ R1.8 #5). Ask for `WebFetch`, which the sandbox domain list does not limit (R1.6.2); cost: a prompt per fetch. |
   172	  | `requiredMinimumVersion` | ≥ 2.1.295, the first version with the hook option `onFailure: "block"` (R1.5.2), and ≥ the latest fixed advisory at rollout (R6.3.9). It does not end running sessions and fails open on a bad value (R1.1.13). |
   173	  | `allowedProviders` + `forceLoginOrgUUID` | `["anthropic"]` + Papaya's org; closes most bypasses on **endpoint-managed** machines (R1.1.15). `forceLoginOrgUUID` checks claude.ai sign-ins only, not Console API keys (R5.5.5). |
   174	  | `allowManagedHooksOnly` | `true` (R1.5.4). |
   175	  | sandbox | `sandbox.enabled`, `failIfUnavailable`, `allowUnsandboxedCommands: false`, narrow `network.allowedDomains` locked by `network.allowManagedDomainsOnly`; `credentials` / `filesystem.denyRead` on `~/.aws`, which the sandbox can otherwise read (R1.6.3, R1.6.4). |
   176	  | MCP, plugins | Layer 4. |
   177	  | OTel | Exporter on, content flags `0` (R1.1.20, R5.5.4). |
   178	
   179	- **Trade-off on AWS credentials.** With `~/.aws` hidden from the sandbox, `aws`, `pulumi` and
   180	  `serverless` must be `sandbox.excludedCommands`, which run "with full access", network included
   181	  (📖 R1.6.4). So these tools are an egress channel outside the allowlist. Accepted because the
   182	  engineer holds no **standing** prod write and no **standing** PHI read; during a JIT or data-read
   183	  window this rests on the process rule in layer 1 (D2). The deny still stops other programs from
   184	  taking the credentials. Stronger option, phase 3: a separate OS user or container for prod-reading sessions
   185	  (⚠️ R6.5 #2).
   186	- **Session types:**
   187	
   188	  | Session | Identity | Flags | Enforcement |
   189	  |---|---|---|---|
   190	  | Daily development (laptop) | non-prod roles + `ProdReadMetadata` | baseline | Auto mode by choice (D1); `--restricted` recommended (D3). |
   191	  | Incident analysis (laptop) | meant to be `ProdReadMetadata` only | `--restricted --tools "Bash,Read,Grep,Glob"`, started in an empty scratch directory, not the repo [design] | Process rule (D3, research 6.9.4 Q1–Q2). No Edit/Write/WebFetch (📖 R6.9.1b), but Bash can still write in its working directory (📖 R1.6.3) and call any role in the cache. |
   192	  | CI agent (hosted runner) | own GitHub App token; never `production` | `--restricted`, explicit `--tools`; all rules in a managed-settings file on the runner | Workflow file under CODEOWNERS (D3, research 6.9.4 Q5). The file is advisory if `Bash` is in `--tools` (layer 5). |
   193	  | JIT terminal | JIT grant | no agent | Process rule (D2). |
   194	  | Auto-mode environment (phase 3) | non-prod only | auto encouraged | D1 option (c). |
   195	
   196	- **Hard limits:** Bash rules are not a boundary (📖 R1.2.6); hooks fail open unless
   197	  `"onFailure": "block"` (📖 R1.5.2); `--restricted` cannot be forced on laptops (📖 R6.9.1, R6.9.1c);
   198	  on laptops **without MDM**, a different login, an API key or a `CLAUDE_CODE_USE_*` variable skips
   199	  server-managed settings, `allowedProviders` included (📖 R1.1.7; ⚠️ R1.8 #3, G11). So S5's
   200	  "nobody can turn off all prompts unnoticed" is likely unreachable without MDM (⚠️).
   201	- **Auto memory:** engineers review it and delete it after a suspicious session; residual risk with a
   202	  named owner (D3).
   203	- **Fallback:** switch to `disableAutoMode` (📖 R1.2.2) if the planted-injection test steers auto mode, a serious
   204	  advisory appears, or an audit finds auto mode touched a protected scope (D1).
   205	
   206	**Audit evidence.** Managed settings in git with PR approvals; `/status` and `claude doctor` from
   207	sampled machines (📖 R1.1.18); OTel `claude_code.tool_decision` (`permission_mode`) and
   208	`claude_code.tool.blocked_on_user` (`duration_ms`, rubber-stamping signal) (fields 📖 research 6.6
   209	D1 metrics; thresholds ⚠️). Settings-change audit events on Team: unknown (⚠️ R1.1.12).
   210	
   211	**Cost / value.** More prompts than auto mode, partly offset by the read-only allowlist. Compliance
   212	gets one organization policy with evidence instead of personal choices (P3c).

   216	## Layer 3 — Change workflow by risk level
   217	
   218	**Principle.** The level is set by the damage a change can do. One default path above non-prod: a
   219	reviewed PR applied by the pipeline, with the JIT fallback (layer 7) as the only other write path.
   220	The approver reviews the code change that will be applied. Higher risk adds a second, specialised
   221	approver. Incidents use the same path with faster people, not fewer security checks.
   222	
   223	| Level | What | Examples | Approval | Path |
   224	|---|---|---|---|---|
   225	| **L0** | Read: non-prod anything; prod metadata | metrics, redacted logs | none | read-only identity |
   226	| **L1** | Change in non-prod | deploy a branch to dev; `pulumi preview` on non-prod (needs state-write permission, 📖 R4.3.3) | author only | non-prod roles or PR pipeline |
   227	| **L2** | Routine prod change in code | Lambda timeout/memory, ECS desired count, release, `CLAUDE.md` | 1 code owner ≠ author, ≠ last pusher | PR → `main` → deploy workflow |
   228	| **L3** | High-risk prod change | IAM/SCP; replace/delete of stateful resources; network; `.github/**`, CODEOWNERS, `.claude/**`, `.claude.json`, `.mcp.json`, `.husky/`, `.gitmodules`, plugin/MCP catalogue; advisory policy finding | 2 distinct humans, at least one platform approver | same path, second approval by path rule or risk stop |
   229	| **L3-JIT** | Break-glass | ECS force-redeploy while Actions is down | on-call approver ≠ requester (Options §4b); if the commands touch IAM, network or stateful resources, also a platform approver [design] | layer 7 |
   230	| **L3-data** | Real customer data read | one tenant's failed claim record | data owner + approver ≠ requester, with an agreement (GĐ-9) | layer 6 |
   231	
   232	`CLAUDE.md`, `CLAUDE.local.md` and `.ripgreprc` are L2, so that moving shared knowledge into
   233	`CLAUDE.md` (D3) stays cheap (OQ3).
   234	
   235	**On Papaya's stack**
   236	
   237	- **Gate = merge to `main`.** On Team, environment reviewers do not exist for private repos
   238	  (📖 R3.1.2). Ruleset on `main`: PR required, 1 approval, code-owner review, dismiss stale approvals,
   239	  approval by someone other than the last pusher, required checks from a pinned source app, no force
   240	  push, empty bypass list (📖 R3.2.2, R3.2.3, R3.2.5). Branch up to date before merge, since there is
   241	  no merge queue (⚠️ R4.6 #1; whether updating drops approvals is open, Options §8).
   242	- **L3 approvals [design]:** a path rule requires 1 platform approval on L3 paths (📖 R3.2.4). Because
   243	  any one code owner satisfies code-owner review (📖 R3.2.7), one platform member could satisfy both
   244	  rules alone (⚠️ inference); a required check with a pinned source app (📖 R3.2.5) therefore confirms
   245	  two distinct human approvers. At 2 a.m. this needs the platform on-call plus one other approver.
   246	- **Risk stop [design]:** the deploy job previews prod; on stateful replace/delete, an IAM change or
   247	  an advisory policy finding it stops. A second PR adds `deploy-approvals/<sha>.yaml` with the
   248	  preview hash; a platform approver who did not approve the original PR approves (checked as above);
   249	  the job continues only if the hash matches (Options §1; hash stability ⚠️ Options §8). A
   250	  `mandatory` policy violation always blocks `pulumi up` (📖 R4.2.2): the fix is a code change, or a
   251	  change to the policy pack through its own L3 PR. Preview output is filtered for
   252	  outputs and secrets before it is posted (Options §1; ⚠️ R4.6 #2).
   253	- **Merge approval = deploy approval** only if (⚠️ R3.6 #1, from 📖 R3.1.3, R3.4.5c): `production`
   254	  allows only `main`; only the reusable deploy workflow (under CODEOWNERS) references it; no ref/SHA
   255	  inputs; no `issue_comment`, `pull_request_target` or `workflow_run` triggers; one concurrency group
   256	  per stack without `cancel-in-progress` (📖 R4.1.4).
   257	- **Pulumi:** PRs preview non-prod only, because a prod preview runs PR code with state-write and
   258	  secret access (📖 R4.3.3, R4.3.4; ⚠️ R4.6 #2). On `main`: prod preview, then `pulumi up` with the
   259	  policy pack, which stops on a mandatory violation (📖 R4.2.2). Prod runs allow no `--skip-preview`
   260	  (📖 R4.1.2) and no targeting, replace, `state`, `import`, `destroy` (⚠️ R4.6 #3, G12). Pulumi Cloud,
   261	  if used: OIDC via `pulumi/auth-actions`, no stored token (📖 R4.1.4).
   262	- **Serverless v4:** `serverless package`; `serverless diff --json` (sf-core ≥ 4.37.0), parsed by CI
   263	  because differences do not change the exit code (📖 R4.4.2); `serverless deploy --package`
   264	  (📖 R4.4.3); a least-privilege `deploymentRole`, which cannot be removed later and is usable by
   265	  anyone who may operate the stack (📖 R4.4.5), so JIT roles get no stack-operation rights.
   266	- **State:** writable only by deploy roles; readable also by the drift role (layer 7); Pulumi
   267	  secrets via `awskms` on a DIY backend (📖 R4.3.3, R4.3.4; ⚠️ R4.6 #7).
   268	- **k0s [design]:** manifests in the monorepo, applied by CI; no write RBAC for humans or agents in
   269	  prod; read roles exclude logs and exec in namespaces with claim data (mechanism: G1).
   270	- **Incident lane:** label `incident`, on-call approver paged, security checks always run (S10), only
   271	  slow unrelated tests skipped [design].
   272	
   273	**Example: Lambda timeouts at 2 a.m.** (Options §6)
   274	
   275	1. The incident-analysis session reads metrics and redacted logs and proposes `timeout` 30 → 90 s,
   276	   memory 1024 → 2048 MB, and a larger visibility timeout on the source queue (ratio ⚠️ Options §8).
   277	2. A second session (edit tools; not meant to use prod roles) edits `serverless.yml`, runs
   278	   `serverless diff` on non-prod, and opens a PR labelled `incident` as the engineer.
   279	3. The on-call approver reviews the diff, and can catch a missing queue change, then approves.
   280	4. The deploy workflow packages, previews prod, finds no risky change, deploys with the OIDC role.
   281	5. Estimate 11–46 min (⚠️ Options §6) against ≤ 30 min: measured first in rollout.
   282	
   283	**Audit evidence.** The PR (diff, approvers, checks); run log and preview artifact, exported because
   284	retention is unverified (⚠️ G7); deploy-role CloudTrail events; all linked by commit SHA and run ID.
   285	
   286	**Cost / value.** One approval for routine prod changes, two for risky ones, none in non-prod.
   287	Compliance gets four-eyes enforced by GitHub. Gap: on Team the prod diff is not seen before apply.

   295	Review takes ≤ 5 working days (S6), or people work around it.

   304	  `allowManagedHooksOnly`, plugin hooks run only for force-enabled plugins (📖 R1.5.4). User mods are
   305	  blocked by the `allowManagedModsOnly` option under `pluginConfigs` → `cc-plugin-sec-default@builtin`

   307	- **MCP:** "approved catalogue" = `allowedMcpServers` + `allowManagedMcpServersOnly: true`; without
   308	  the lock users can widen it (📖 R1.3.1, R1.3.4). Match by `serverUrl` or `serverCommand`, never
   309	  `serverName` ("not a security control", 📖 R1.3.3); the argv pins an exact version (⚠️ R6.4.4).

   313	  it sends data, with a supplier-register entry and BAA/DPA status (⚠️ R5.6); no token passthrough
   314	  (📖 R6.4.2); write tools for Slack, Linear, GitHub only where needed (⚠️ R6.5 #6); pinned version,

   328	## Layer 5 — CI/CD hardening
   329	
   330	**Principle.** CI is the default production writer, so it is the main target. Short-lived,
   331	least-privilege credentials per job. Every CI dependency is pinned. Agent-written code passes the same
   332	checks as human code (S10).
   333	
   334	**On Papaya's stack**
   335	
   336	- **Credentials:** OIDC instead of keys and tokens in repository secrets, which any writer can read
   337	  (📖 R3.4.1, R3.5.3b). Org default for `GITHUB_TOKEN` set to "restricted", `permissions:` per job (📖 R3.5.3).
   338	  "Allow GitHub Actions to create and approve pull requests" off (📖 R3.3.3). Serverless License Key in
   339	  SSM, read by the deploy role (sf ≥ 4.4.19, 📖 R4.4.8). Until G1/G2 are solved, k0s and Firebase
   340	  deploys may still need a stored credential: a proposed time-boxed exception to S2 = 0 (OQ1).
   341	- **Side paths:** Pulumi ESC, Pulumi Deployments and Serverless Dashboard providers reach AWS
   342	  (📖 R4.4.9) outside the GitHub gate (⚠️ R4.4.9); not used for prod (⚠️ R4.6 #6).
   343	- **Pinning:** workflow lockfile (`gh actions-lock`) or full SHA, enforced by the org policy "Require
   344	  actions to be pinned to a full-length commit SHA"; the lockfile does not pin reusable workflows, so
   345	  the deploy workflow lives in the same repo (📖 R3.5.5).
   346	- **CODEOWNERS** on `.github/`, `CLAUDE.md`, `CLAUDE.local.md`, `.claude/`, `.claude.json`, `.mcp.json`,
   347	  `.husky/`, `.gitmodules`, `.ripgreprc` (📖 R3.2.8; list ⚠️ R6.5 #5); CI validates the file, because
   348	  invalid lines are skipped silently (📖 R3.2.7).
   349	- **No privileged triggers with untrusted code** (`pull_request_target`, `workflow_run` + checkout,
   350	  📖 R3.5.4).
   351	- **Agents in CI:** `claude-code-action` with a custom GitHub App limited to Contents, Issues, Pull
   352	  requests (📖 R1.7.8); Anthropic workload identity federation, not a personal OAuth token (📖 R1.7.6);
   353	  `--restricted` and explicit `--tools` (D3; passing it through `claude_args` unverified, ⚠️ research
   354	  6.9.4 Q5); a managed-settings file on the runner, which also guards against mods (📖 R1.5.6; for
   355	  federation auth ⚠️); MCP set fixed by CI because `.mcp.json` loads without a prompt in `-p` runs
   356	  (📖 R1.3.5); never `environment: production` (⚠️ R3.6 #4). Hosted runners give `sudo` (📖 R3.5.1),
   357	  so with `Bash` in `--tools` the runner file is advisory (⚠️ R3.5.1, R3.6 #4).
   358	- **App-opened PRs:** a required check with a pinned source app confirms at least one approval by a
   359	  human who did not trigger the run; counting approvals is not enough, since the app's own approval
   360	  might count (⚠️ R3.3.4, R3.7 A3; 📖 R3.2.5).
   361	- **Required checks (S10):** secret scanning, dependency check, SAST (products: G4); IAM Access
   362	  Analyzer `check-no-new-access` (📖 R2.8.1); Pulumi policy packs (📖 R4.2.2).
   363	
   364	**Audit evidence.** Workflows and lockfile in git; audit-log events such as
   365	`org.update_actions_secret`, `repo.set_workflow_permission_can_approve_pr`, `repository_ruleset.update`
   366	(📖 R3.3.3, R3.5.6); check results per PR; secrets inventory (S2).
   367	
   368	**Cost / value.** One-time migration to OIDC and pinned actions; slower action updates. Compliance
   369	gets S2 and the same guardrails for agent and human code.

   373	## Layer 6 — Data protection and prompt-injection defence
   374	
   375	**Principle.** PHI never reaches the coding agent (owner decision, research 1.9). Other customer
   376	personal data is outside that hard boundary ("not extended", research 5.8): the agent reads metadata
   377	by default and may read such data case by case under GĐ-9. Real-data reads are approved,
   378	tenant-scoped, time-boxed, and need an agreement (BAA/DPA, partner contract) (GĐ-9). Everything read
   379	from outside is untrusted. Non-prod is synthetic (GĐ-14).
   380	
   381	**On Papaya's stack**
   382	
   383	- **Paths to PHI** (research 1.11.4 lists 17):
   384	  - AWS stores: closed by identity, through `ProdReadMetadata` from phase 1 and the SCP from phase 2
   385	    (layer 1); no Aurora credentials, no prod exec, no `lambda:InvokeFunction` for agent-usable roles
   386	    [design; actions ⚠️ G13];
   387	  - k0s logs/exec and GCP stores (L1, L11, L13): same principle, mechanism open (G1, G3);
   388	  - tickets/chat via MCP, pasted text, internal admin pages, prod AI traces, fixtures, CI logs (L5,
   389	    L8–L10, L12, L14): process and hygiene only;
   390	  - logs redacted at source with raw payloads in a separate log group; alerts carry IDs, not payloads [design].
   391	- **Real-data request** [design]: tenant, purpose, store, window, agreement; approved by the data owner
   392	  and an approver ≠ requester; JIT data-read role, 1 h. Per-tenant scoping through session tags
   393	  (📖 R2.1.8) is unresolved, because tags come from user attributes (⚠️).
   394	  - **PHI:** a human reads in a terminal without an agent (process rule, layer 1); the agent gets a
   395	    redacted summary. This
   396	    narrows GĐ-9 because the agent stays outside PHI scope (research 1.9) and Team is not shown as
   397	    BAA-covered (⚠️ R1.11.3.4). Enterprise + BAA only for a separate environment if needed (research 1.9).
   398	  - **Non-PHI personal data:** the agent may read it within the approved request (GĐ-9).
   399	- **Partner-uploaded claim documents (A7b):** never in an agent session raw; reproduce with synthetic
   400	  documents, or de-identify first [design]. The document is PHI and an injection vector (research
   401	  1.11.4 L6).
   402	- **Injection** (these lower frequency; layers 1 and 3 limit impact): Manual by default; the auto-mode
   403	  classifier missed 17 % of 52 real overeager actions (📖 R6.3.5). Broad allowed domains such as
   404	  `github.com` are a documented exfiltration path (📖 R6.3.7). The incident session has no edit tools
   405	  and runs outside the repo, but its Bash can still write locally and send data out through excluded
   406	  commands (layer 2); what is at stake is bounded by "no standing write, no PHI read". Shared knowledge
   407	  goes in `CLAUDE.md` under review; auto memory is unprotected unless `--restricted` (📖 R6.3.11, D3).
   408	- **Tenants:** one tenant per data-read grant; a session that read one tenant's data does not post to
   409	  shared places without review (⚠️ R6.5 #8, process). Logical separation in shared accounts is assumed
   410	  (GĐ-3).
   411	- **Non-prod:** no prod copies (S11). A scan of non-prod stores runs at the start of phase 1 (tool:
   412	  G4); a store not yet scanned follows the L3-data rule (GĐ-14). Cost: until scanned, that store is
   413	  not part of the free loop.
   414	- **Local stores:** transcripts and memory hold what the agent read (research 1.11.4); set
   415	  `cleanupPeriodDays` (30 in the HIPAA sample, 📖 R5.5.4; what it deletes ⚠️).
   416	- **Cross-border (Vietnam example):** processing data collected in Vietnam on a platform abroad is a
   417	  transfer (📖 R5.4.5); agent flows, including employee names in logs and transcripts, update the
   418	  transfer impact assessment (⚠️ R5.7 #4, needs Papaya legal).
   419	
   420	**Audit evidence.** SCP/IAM text as the written access rule for sensitive data (📖 R5.4.3; ⚠️ R5.7 #5);
   421	data-read requests and the data-read role's CloudTrail; planted-injection reports (layer 8); non-prod
   422	scan results (S11).
   423	
   424	**Cost / value.** Debugging with redacted and synthetic data; a request for the rare real-data read.
   425	Compliance gets "minimum necessary" (📖 R1.11.1.8) enforced by IAM, and a record per exception (S9).

   429	## Layer 7 — Observability, audit, incident response and break-glass
   430	
   431	**Principle.** One tamper-evident evidence chain per prod change. One routed alert channel with a
   432	named on-call, approvers included. Unapproved change is detected (drift, reconciliation). Break-glass
   433	is approved before use, time-boxed and reconciled after.
   434	
   435	**On Papaya's stack**
   436	
   437	- **Audit stores:**
   438	  - organization CloudTrail to a log-archive account with integrity validation (📖 R2.6.2, R2.6.4,
   439	    R2.6.5); change records ≥ 6 years; raw-log retention for Papaya's compliance owner (⚠️ R5.7 #2).
   440	    Data events only on PHI buckets, prod Lambda invoke and prod SQS (📖 R2.6.3), which makes the archive
   441	    PHI-bearing (⚠️ research 1.11.4 L15). CloudTrail Lake is closed to new customers (📖 R2.6.6);
   442	  - GitHub org audit log kept 180 days, so exported (📖 R3.5.6);
   443	  - alerts on `repository_ruleset.update`, `environment.update_protection_rule`,
   444	    `environment.remove_protection_rule`, `environment.delete`, `protected_branch.policy_override`
   445	    (📖 R3.5.6, R3.1.4; selection ⚠️ R3.6 #1). UI changes to the branch policy may leave no event, and a
   446	    deleted `production` environment comes back unprotected (⚠️ R3.1.4): a job compares live settings
   447	    with an expected copy (G8);
   448	  - Aurora SQL is likely invisible to CloudTrail (⚠️ R2.7.1): Database Activity Streams, alerts on
   449	    lost-record events (📖 R2.7.2; Serverless v2 ⚠️), stream treated as PHI (⚠️ R2.7.3);
   450	  - Claude Code OTel without prompt content (layer 2).
   451	- **Change record [design]:** keyed by commit SHA or JIT request ID; links PR, approvals, run ID,
   452	  preview and CloudTrail events. Monthly reconciliation: every prod write event matches a record
   453	  approved before apply (S3). Actor: `onBehalfOf.userId` where present, else session name plus
   454	  directory lookup (📖 R2.5.1; ⚠️ R2.5.3).
   455	- **Drift [design]:** its own read role, trusted only from a `drift` environment on `main`; it can read
   456	  prod secrets in state, which is noted (⚠️ R4.6 #2). Scheduled `pulumi preview --refresh
   457	  --expect-no-changes` or `pulumi refresh --preview-only` (📖 R4.1.1, R4.3.1, R4.3.2); CloudFormation
   458	  drift detection, explicitly set properties only (📖 R4.4.6). No auto-remediation: it is an unreviewed
   459	  `pulumi up --refresh` (📖 R4.3.2). Each finding gets an actor and a ticket.
   460	- **On-call:** phase 1 delivers only the named approver schedule (primary + backup, 24/7), as decided
   461	  in framing round 1, including a platform approver because L3 needs one (Options §1). Alert routing and
   462	  the rest of on-call follow in phase 2 (tools: G5).
   463	- **Break-glass = JIT fallback** [design unless marked]:
   464	
   465	  | Step | Rule |
   466	  |---|---|
   467	  | When | The PR path cannot be used: operation not in IaC and no runbook; GitHub/Actions down; pipeline broken. The approver refuses JIT for anything expressible in IaC while the pipeline works, and records why. |
   468	  | Request | Command list, scope, reason, incident link, in a channel that does not depend on GitHub. |
   469	  | Approval | On-call approver ≠ requester, before the grant. |
   470	  | Grant | `InfraOperator-<service>`, 1 h (📖 R2.1.4). Deleting the assignment likely stops only new sessions (⚠️ R2.4.2, R2.9 #3); ending the portal session does not end role sessions (📖 R2.4.3); an immediate stop needs the revocation SCP (📖 R2.4.4). |
   471	  | Execution | The human types the commands; no agent in that terminal (D2). |
   472	  | After | A job compares CloudTrail writes in the window with the list; a codify PR within a fixed deadline (as soon as GitHub is back); drift detection until it merges. |
   473	  | Identity Center outage | Emergency SAML federation to roles, built and tested in advance (📖 R2.1.11; ⚠️ R2.9 #2); no user mapped until an approved activation, which is alerted. |
   474	
   475	  **Example request (illustrative command ⚠️):** "INC-123, `claims-doc-extract`, Actions outage. Run
   476	  `aws ecs update-service --cluster <prod-cluster> --service <svc> --force-new-deployment`. Scope
   477	  `InfraOperator-claims`, 1 h."
   478	
   479	  **Metrics** (Options §7; starting thresholds ⚠️ to calibrate): JIT used where a PR was possible
   480	  (review at 1); writes outside the list (review at 1); codify PRs late (review at 1); grants per
   481	  month and share of incidents needing non-IaC operations (review above about 25 %, a value new in
   482	  this draft). On a breach,
   483	  make the PR lane faster or add a runbook; do not widen JIT.
   484	- **Roadmap:** runbooks for repeated non-IaC operations, if SSM Automation's approval step meets three
   485	  conditions (Options §2; outside 02-research, G6); break-glass from an environment without the agent
   486	  (D2, ⚠️).
   487	
   488	**Audit evidence.** Validated CloudTrail; exported GitHub audit log; change records and monthly
   489	reconciliation (S3, S8 ≤ 30 min); JIT requests, reconciliations, codify PRs; drift tickets; on-call
   490	schedule and approval waits (S7).
   491	
   492	**Cost / value.** The incident lane is slower than direct access (estimated 11–46 vs 2–20 min,
   493	Options §6), and JIT needs a written command list. Compliance gets approval before apply even in
   494	incidents, plus detection.
